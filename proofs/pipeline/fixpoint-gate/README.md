# The Fixpoint axiomatisation gate

`AgnosticPipeline.AgSmt` gives `Space.Fixpoint` a FIRST-CLASS first-order denotation: an
uninterpreted `fix : Path -> Bool` constrained by the two post-fixpoint axioms

    forall q. init(q)              -> fix(q)
    forall q. body{rec := fix}(q)  -> fix(q)

plus one PARK INDUCTION instance per ordered pair of fixpoints occurring in the same obligation

    (forall r. init_f(r) -> g(r)) /\ (forall r. body_f{rec := g}(r) -> g(r))
      ->  forall q. fix_f(q) -> g(q)

An OVER-STRONG version of this — leastness asserted without its premises, or `fix` simply defined
to be the union of the iterates — would make every enclosing obligation vacuously provable, which
is the exact failure mode plan item 12 exists to fix. These four files are the gate. They are
generated by the real emitter (`AgnosticPipeline.smtAgnostic`) and are NOT part of the pipeline
matrix; they live in this subdirectory so `scripts/audit_pipeline_markers.py`, which globs only the
top level of `proofs/pipeline/`, does not classify a deliberately-false file.

| file                  | statement                                                    | must be |
|-----------------------|--------------------------------------------------------------|---------|
| `fix-true.smt2`       | lfp(src, X -> X u {a}) = lfp(src u {a}, X -> X u {a})          | PROVED  |
| `fix-false-body.smt2` | lfp(src, X -> X u {a}) = lfp(src, X -> X u {b})                | OPEN    |
| `fix-false-init.smt2` | lfp(src, X -> X u {a}) = lfp(0,   X -> X u {a})                | OPEN    |
| `fix-false-iter.smt2` | lfp(src, X -> X u {a}) = lfp(src, X -> X u ({a} n src))        | OPEN    |

## The second premise: what the executors iterate

`terminating/fixpoint_is_lfp.smt2` (O1) needs TWO hypotheses, monotone `F` **and** `init subset=
F(init)`, and carries a machine-checked monotone-but-non-inflationary counterexample at :47-50:

    F(X) = {b if a in X} u {c if a in X and b in X},   init = {a}

Under that `F`, iterating `F` and accumulating on the side returns `{a,b}` while the least post-
fixpoint above `init` is `{a,b,c}` — and `{a,b,c}` is what the axioms at the top of this file say.
Every syntactic monotonicity gate in the tree accepts this `F`, so monotonicity alone did not stand
between the executors and that gap.

It is closed by CONSTRUCTION rather than by a second check: every executor
(`MORKL.eval`/`exec`, `GraphExec.execT`, `Trie.evalT`, `IntTrie.evalI`) iterates the INFLATIONARY
operator `cur := cur u F(cur)`, whose chain ascends whatever `F` is. Monotonicity is then the one
remaining side condition, and it is exactly what buys LEASTNESS.

`src/test/scala/FixpointSemantics.scala` generates and checks five more files here. The first two
are emitted by the real `AgnosticPipeline.smtAgnostic`; the last three are a hand-written decidable
twin (a set over `{a,b,c}` as a `(_ BitVec 3)`), so a bug in the Space -> SMT emitter cannot make
both agree, and so the NEGATIVE control produces a refutation instead of a timeout.

| file                          | statement                                          | must be     |
|-------------------------------|----------------------------------------------------|-------------|
| `lfp_agrees.smt2`             | the counterexample's `Fixpoint` = `{a,b,c}`        | PROVED      |
| `accumulator_refuted.smt2`    | the counterexample's `Fixpoint` = `{a,b}`          | NOT PROVED  |
| `bv_lfp_pinned.smt2`          | decidable: axioms force `fix = {a,b,c}`            | unsat       |
| `bv_accumulator_refuted.smt2` | decidable: `fix = {a,b}` contradicts the axioms    | unsat       |
| `bv_nonvacuity.smt2`          | decidable: the axioms have a model (`fix={a,b,c}`) | sat         |

MEASURED 2026-09-02 (z3 5.1.0, vampire 5.1.0), and recorded in this directory's `STATUS.tsv`:

    lfp_agrees.smt2               z3 unsat        vampire "Refutation found"
    accumulator_refuted.smt2      z3 timeout 60s  vampire no refutation at 60 s
    bv_lfp_pinned.smt2            z3 unsat
    bv_accumulator_refuted.smt2   z3 unsat        <- the decisive one: {a,b} is REFUTED, not
                                                     merely unproven
    bv_nonvacuity.smt2            z3 sat, fx = #b111

The `accumulator_refuted.smt2` timeout is why the decidable twin exists: over the full path
datatype the models are infinite path sets and neither prover builds one, so "not discharged" is
all the ∀-path file can say. The `(_ BitVec 3)` twin closes that with an actual refutation.

MEASURED 2026-08-31 (z3 5.1.0, vampire 5.1.0, `--input_syntax smtlib2`, default mode):

    fix-true.smt2         z3 unsat 0.01 s            vampire "Refutation found"
    fix-false-body.smt2   z3 timeout at 120 s        vampire no refutation at 120 s
    fix-false-init.smt2   z3 timeout at 120 s        vampire no refutation at 120 s
    fix-false-iter.smt2   z3 timeout at 60 s         vampire no refutation at 60 s
    fix-false-{body,init} z3 smt.mbqi=true, 30 s: timeout (no countermodel found either)

So the axioms are strong enough to prove a genuine fixpoint equality and NOT strong enough to
prove a false one. The `timeout` (rather than `sat`) on the false files means neither prover
produced a countermodel inside the budget — the models are infinite path sets — which is why the
gate is stated as "must NOT be discharged" rather than "must be refuted".

Reproduce (z3 and vampire are found by `toolchain.conf`: `$Z3`/`$VAMPIRE`, then `$ZIPPY_TOOLS`,
then `PATH` — see `docs/guide.md` for installing them):

    for f in proofs/pipeline/fixpoint-gate/fix-*.smt2 \
             proofs/pipeline/fixpoint-gate/{lfp_agrees,accumulator_refuted}.smt2; do
      echo "== $f"; z3 -T:120 "$f"; vampire --input_syntax smtlib2 -t 120s "$f" | grep -c "Refutation found"
    done
    for f in proofs/pipeline/fixpoint-gate/bv_*.smt2; do echo "== $f"; z3 -T:30 "$f"; done

or regenerate and re-check every file in one step:

    sbt 'testOnly morkl.FixpointSemantics'
